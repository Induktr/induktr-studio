# 🏛️ Induktr Studio Architectural Invariants Protocol (Rules 11-13)

Настоящие правила сформулированы субагентом-философом (`tsd-cognitive-philosopher`) на основе Первых Принципов (TSD v27.2.2), валидированы и утверждены системным Rust-валидатором (`rule_validator.exe`, 100% PASS) и являются обязательными инвариантами монорепозитория Induktr Studio.

## 11. 🛑 Правило Детерминированного Жизненного Цикла L1-Кэша (Native SQLite & Buffer Invariants)
* **Ограничение:** Запрещено использовать нативные in-memory базы данных (такие как Bun:sqlite `Database(':memory:')`) или неструктурированные долгоживущие буферы кэширования без явного ограничения предельного размера (LRU / FIFO capping), автоматической очистки по времени жизни (TTL sweep) и обязательной деаллокации в хуках завершения жизненного цикла приложения (`onModuleDestroy` / `close`), допуская бесконтрольный рост неуправляемой C++ памяти за пределами сборщика мусора V8.
* **Контрмера:** Принцип First-Principles изоляции нативных структур (НУ-детерминизм): любая runtime-аллокация нативного хранилища L1 (Bun:sqlite, shared buffers, typed ring buffers) обязана инкапсулироваться внутри строгого интерфейса с детерминированным пределом емкости (`MAX_CACHE_ENTRIES`), скользящим временным окном устаревания (TTL eviction pruning при каждой записи) и явным вызовом `db.close()` при деструкции NestJS/Bun контекста. Это гарантирует сохранение плоской топологии V8-кучи, отсутствие утечек за пределами Garbage Collector и защиту сервиса от деградации памяти при многодневных нагрузках.
* **Последовательность шагов:**
  1. Задать константы жесткого лимита емкости кэша (`MAX_CACHE_SIZE`) и интервала устаревания (`TTL_MS`).
  2. При создании SQLite-схемы добавить индекс по `created_at` и автоматическую транзакционную очистку старых записей при превышении порога.
  3. Реализовать интерфейс `OnModuleDestroy` в NestJS сервисе с явным закрытием подготовленных выражений (`Statement.finalize`) и базы данных (`db.close`).
  4. Провести профилирование Resident Set Size (RSS) в Bun runtime под симулированной нагрузкой в 100 000 итераций.
* **Сфера:** Архитектура & Безопасность, Backend & Memory, Bun Runtime Engine.
* **Цена нарушения:** Утечка нативной C++ памяти вне контроля V8/JSC GC, деградация RSS до Out-Of-Memory (OOM-killer) краша процесса Bun, сохранение невалидного стейта между перезапусками тестов.
* **Технологии:** TypeScript, Bun, V8 Engine, First Principles (НУ), SQLite.

## 12. 🛡️ Правило Криптографической Неприкосновенности Инициализационных Данных (Anti-Replay & Sterile Ingestion)
* **Ограничение:** Запрещено валидировать криптографические подписи внешних платформ (Telegram WebApp initData, OAuth state, Webhook HMAC) без строгой проверки временного окна актуальности метки времени (`auth_date` Freshness Window), запрещено декодировать полезную нагрузку в несанитизированные объекты окружения через сырой `JSON.parse` без пропуска через схему Zod и стерильный проектор с null-прототипом, и категорически запрещено допускать безусловный пропуск авторизации при отсутствии секретных токенов окружения.
* **Контрмера:** Протокол First-Principles криптографической верификации: вычисление HMAC производить строго в константном времени с предварительной проверкой фиксированной длины дайджеста через `timingSafeEqual`, гарантировать свежесть токена проверкой `Math.floor(Date.now() / 1000) - authDate <= MAX_EXPIRATION_WINDOW_SEC` для абсолютной защиты от Replay-атак, а десериализацию пользовательских сущностей выполнять исключительно через стерильный словарь `pickWhiteList` и Zod-контракт. При отсутствии конфигурационных секретов сервер обязан падать с фатальной ошибкой конфигурации (Fail-Fast), исключая bypass-уязвимости.
* **Последовательность шагов:**
  1. Извлечь и верифицировать параметр `auth_date` против текущего времени сервера с допуском не более 86400 секунд (или 300 секунд для мгновенных транзакций).
  2. Выполнить проверку длины хэш-буфера (строго 32 байта для SHA-256) и произвести криптографическое сравнение через `timingSafeEqual`.
  3. Распарсить поле `user` и пропустить через проекцию на null-прототип через `pickWhiteList`.
  4. Исключить fallback-условия обхода проверки при отсутствии токена в non-production, заменив на явный запрет аутентификации.
* **Сфера:** Архитектура & Безопасность, Криптография, Object (JAVASCRIPT).
* **Цена нарушения:** Уязвимость повторного воспроизведения (Replay Attack), компрометация учетных записей пользователей через устаревшие дампы подписей, прототипное загрязнение через несанитизированный JSON, несанкционированный доступ к защищенным роутам.
* **Технологии:** TypeScript, Bun, V8 Engine, First Principles (НУ), HMAC-SHA256.

## 13. ⚡ Правило Изоляции Высокочастотных Потоков Рендеринга (Zero-Reflow RAF & Active Lifecycle)
* **Ограничение:** Запрещено запускать непрерывные высокочастотные циклы анимации (`requestAnimationFrame` / `setInterval` 60Hz) в модульных синглтонах без учета активных подписчиков (Reference-Counted Subscription Barrier), запрещено модифицировать геометрические свойства DOM-элементов (`height`, `width`, `top`, `margin`), вызывающие синхронный перерасчет геометрии дерева Layout/Reflow, и запрещено производить прямую мутацию внешних объектов состояния во время фаз реконсиляции React без обеспечения неизменяемости снимка для `useSyncExternalStore`.
* **Контрмера:** Метод First-Principles изоляции реактивных потоков (НУ-оптимизация): модульный движок телеметрии обязан переходить в спящий режим (Idle State) и останавливать RAF при `listeners.size === 0`, возобновляя квантование только при появлении активных потребителей. Визуализация столбиков эквалайзера и индикаторов обязана осуществляться исключительно через GPU-композитные трансформации (`transform: scaleY(...)` с `transform-origin: bottom`) вместо модификации геометрии `height`, а снимки внешнего хранилища обязаны быть иммутабельными и возвращать замороженный детерминированный серверный снимок на этапе SSR.
* **Последовательность шагов:**
  1. Добавить счетчик активных слушателей в `telemetryEngine` и стартовать цикл RAF только при `listeners.size === 1`, а при `listeners.size === 0` вызывать `cancelAnimationFrame`.
  2. Заменить прямое изменение `bar.style.height = ...` в `EqualizerVisualizer` на аппаратно ускоренное `bar.style.transform = scaleY(...)`.
  3. Зафиксировать статическую замороженную структуру для `getServerSnapshot()`, предотвратив разрывы гидратации.
  4. Исключить CSS-свойство `transition-[height]` на элементах с частотой обновления 60 кадров в секунду для ликвидации микро-фризов.
* **Сфера:** Performance & React, DOM, Архитектура & Безопасность.
* **Цена нарушения:** Утечка ресурсов CPU/аккумулятора в фоновых вкладках и на неактивных экранах, деградация FPS из-за принудительного Layout Reflow 60 раз в секунду, нарушение согласованности снимков в React 19 Concurrent Mode.
* **Технологии:** TypeScript, React 19, V8 Engine, First Principles (НУ), Web APIs.
